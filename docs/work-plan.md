## F0 — Repo and tooling

**Goal:** a working environment in which `kicad-cli` can run ERC and DRC.

1. GitHub repo `nexus` under `bertenvdb` (ask Berten: public or private).
2. Structure:
   ```
   CLAUDE.md
   README.md
   .gitignore
   docs/                 (this documentation)
   lib/                  (nexus.kicad_sym, nexus.pretty/, 3dmodels/, sheets/)
   toolboard/            (KiCad project)
   dockboard/            (KiCad project)
   scripts/              (import, check and export scripts)
   fab/                  (production files per revision)
   out/                  (generated, in .gitignore)
   ```
3. Installation according to `tooling-setup.md`. Check with `kicad-cli version` that it is **10.x**.
4. `scripts/check.sh`: runs ERC and DRC on both boards and returns an exit code ≠ 0 on errors.

**Done when:** empty projects for both boards open without errors, `scripts/check.sh` runs, the first commit is pushed.

## F1 — Parts library

**Goal:** every part from `bom-master.csv` is in `lib/` with a checked symbol, a footprint and a 3D model.

1. First refresh the stock and Basic/Extended status of every line in `bom-master.csv` on jlcpcb.com/parts. Lines marked "TBD" get a concrete C number.
2. `scripts/import_parts.sh`: calls `easyeda2kicad --full --lcsc_id=<C> --output lib/nexus` for every C number in the CSV.
3. For generic passives (0603 R/C) and standard connectors, use the **standard KiCad libraries** (`Resistor_SMD:R_0603_1608Metric`, `Connector_JST:JST_XH_B2B-XH-A_1x02_P2.50mm_Vertical`, …), with the LCSC field filled in.
4. **Check every imported footprint** against the datasheet: pad dimensions, pin 1, exposed pad and thermal vias (SO8-PowerPAD of the TPS54360B, DFN3×3 of the WSD4070DN, SuperSO8 of the BSC016N06NS, WSON of the LM74502).
5. Record the results in `bom-master.csv` (columns `lib_source`, `lib_symbol`, `lib_footprint`, `verified`).

**Review F1:** list of parts with their status, plus deviations and doubtful cases.

## F2 — Pinout and mechanical constraints

**Goal:** pin down what determines the schematic and the layout, **before** you start drawing.

1. **STM32G0B1RBT6 pinout** for both boards in `docs/pinout-toolboard.md` and `docs/pinout-dockboard.md`. Per pin: function, net name, pin type (FT/FT_a/TT), alternate function, rationale. Mandatory checks:
   - VREF+ as a separate pin or not (datasheet, pin table)
   - 9 ADC channels (8 thermistors + RAIL_SENSE) on FT_a pins that do not clash with USB, SWD, FDCAN or the crystal
   - 16 filament inputs (8× RUNOUT + 8× MOTION) on FT pins **without** analog function
   - FDCAN and USB pins supported by Klipper (check the source code)
   - An arrangement that makes the layout logical: heater PWM on the MOSFET side, ADC on the thermistor connector side
2. **Mechanical constraints. Ask Berten for these, do not make them up:**
   - Maximum dimensions of both boards and their location in the printer
   - Mounting holes (number, diameter, position, M3?)
   - Which edges the connectors go on (wiring to the panel, the PSU and the host)
   - Height restrictions (electrolytic caps, XT60)
   - Should the boards be ordered together in one panel (see `design/20-dockboard.md` §8)?
3. **Calculations for the TPS54360B** (both applications): RT, compensation, inductor, output capacitors, FB divider. Use TI WEBENCH or the datasheet formulas. Record them in `docs/calculations.md` (generated by `scripts/calc_f2.py`).
4. **Trace widths and copper:** IPC-2152 calculation for the net classes in `CLAUDE.md` §6 and the power trunk (§6.1). Decide 1 or 2 oz with Berten (cost).

**Review F2:** pinout tables, mechanical drawing or description, calculations.

## F3 — Schematic Nexus Tools Board

**How the schematic is made (2026-11-17).** Every sheet is described in Python (`scripts/schgen/toolboard.py`, part catalogue `scripts/schgen/parts.py`) and generated with `scripts/build_schematic.py toolboard`. Each pin gets a short stub with a power symbol or a label. The build then exports KiCad's own netlist and compares it pin by pin with the description, runs ERC and exports the PDF. UUIDs are derived from stable part keys, so regenerating keeps the PCB links. **Consequence: do not edit the generated `.kicad_sch` files by hand**; change the description and rebuild.

## F5 — Layout Nexus Tools Board

**Step 1 (2026-11-17)** was generated by `scripts/pcbgen/toolboard_place.py`: outline 140 × 90 mm, M3 holes, edge connectors with 1.0 mm overhang, functional blocks packed into regions, net classes in `toolboard.kicad_pro`. Every footprint is linked to its symbol (path), so *Update PCB from Schematic* works. **Step 2 (power + ground zones, fixed trunk and channel placement) was also generated by the same script, still before any manual work. From step 3 (routing) on the `.kicad_pcb` file is the source**: re-running the placement script would discard manual placement and routing.

Work in four steps, **each with a review**. Render after each step (`kicad-cli pcb export svg` / `pcb render`) and look at it yourself first.

1. **Outline and placement:** board outline and mounting holes (from F2), connectors on the edges, functional blocks grouped. Mandatory: compact buck loop, AGND area around the thermistor inputs and the MCU, **power trunk according to CLAUDE.md §6.1** (XT60, main fuse and cutoff FETs side by side along one edge, trunk ≤ 40 mm, fuses + MOSFETs in a row). **Diagnostic LEDs (AD-17) together along one edge that stays visible when installed.**
2. **Power and ground:** polygons for +24V_IN, +24V_HEATER and the GND return on multiple layers, with via stitching. Trunk ≥ 7 mm per layer at 1 oz (≥ 3.5 mm at 2 oz), top + bottom. Thermal copper for the FETs (≥ 4 cm² per cutoff FET). The AGND–GND star point.
3. **Routing:** critical signals by hand first (USB pair, CAN pair, crystal, thermistor traces, buck feedback), then the rest (Freerouting if need be, **never** for power nets).
4. **Finishing:** silkscreen (board name **Nexus Tools Board** clearly legible on the top side, together with revision, date and license (AD-14); tool numbers, pin functions, polarity, solder jumper settings, a label at every diagnostic LED, warning at the fan rail jumper on the dock board), fiducials if needed, DRC = 0, 3D render.

**Step 3 as done (2026-11-17 … 11-20).** Freerouting and a greedy maze router both stalled at 30–50 open connections: with about 1 mm around the MCU, its 50 pins could not fan out. Two changes closed it:
- *Logic re-placement* (`scripts/pcbgen/toolboard_logic_replace.py`, variant `fan`): LDOs, MCU, crystal, SWD/buttons and gate buffer moved so the MCU has ≥ 3.6 mm free on every side; the approved buck layout is unchanged.
- *Negotiated-congestion routing* (`scripts/pcbgen/negotiate.py`, PathFinder, A* kernel in `maze_core.c`): every round rips up and reroutes all nets; other nets' copper costs extra, contested cells get more expensive each round, until no two nets violate clearance.

Pipeline: `toolboard_preroute.py` (heater channels) → `stitch.py` (GND/AGND vias) → `negotiate.py` (`NEG_ALL=1 NEG_ITER=80 NEG_PRES_MAX=20 NEG_HIST=1.0`, no escape lanes) → `cleanup.py` → `maze.py` for the USB pair (one via allowed: the USB-C DP/DM pads alternate) and the small +24V_IN/CUTOFF_SRC branches (sense, test points, LED). In1 carries no tracks. Result: 0 unconnected, 0 copper DRC errors. A layer change to 6 layers was rejected on cost (Berten, 2026-11-20).

**Step 4 as done (2026-11-20).**
- *Analog clearance:* `scripts/pcbgen/analog_check.py` measures how close thermistor/VREF/RAIL_SENSE traces run to switching nets (buck node, heater drains, gates, gate-buffer inputs), same layer and the coupled In2/B.Cu pair. The first routing had two parallel runs (THERM_T4/T7 next to GATE_T7_B on In2, 8–14 mm at 0.5–0.7 mm). The board was rerouted with `NEG_AVOID_MM=1.0` (analog and switching nets pay extra within 1 mm of each other on the same layer); what is left are 28 right-angle crossings and no parallel runs. Full routing: `scripts/pcbgen/toolboard_route.sh`.
- *Ground pours* (`scripts/pcbgen/pours.py`): GND and AGND on F.Cu, In2 and B.Cu with the same split as the In1 plane, below the power zones. SMD pads solid (reflow), THT pads thermal reliefs (hand-soldered connectors), exposed-pad thermal vias solid.
- *Silkscreen* (`scripts/pcbgen/toolboard_silk.py`): reference designators off the silkscreen (they stay on F.Fab; ~340 parts do not fit legibly); function labels instead: T0–T7 at every connector and heater LED, +24V / HEATER− at the screw terminals, filament pin functions (RUN GND VCC MOT), LED port, CAN, SWD, USB, 24V IN, RESET/BOOT, diagnostic LEDs, test points, PT1000 and filament-supply jumpers. Board name + revision/date on top; name, revision/date, CERN-OHL-S-2.0 and repo URL on the bottom (the top has no free area that large). Footprint silk crossing the board edge (overhanging connectors) is trimmed.
- *XT60 polarity fix:* see open item 29.
- *No fiducials:* JLC does not need them for single boards (they use the pads); add rails with fiducials only if a panel is ordered.
- *DRC:* 0 errors, 0 unconnected, schematic parity OK. 12 warnings `lib_footprint_mismatch`, all intentional: the 12 edge connectors whose silk over the board edge was trimmed (J1, J3–J5, J7–J14). KiCad 10's `kicad-cli` did not accept them as exclusions.

**Review F5:** renders of all layers + 3D view + DRC report.

## F6 — Layout Nexus Docks Board

**Step 1 brought forward (2026-11-17, Berten's request):** generated by `scripts/pcbgen/dockboard_place.py`, 88 × 62 mm, 4 layers, as small as possible (mechanical.md §9). Steps 2–4 follow after F5.

Same approach as F5, with **Nexus Docks Board** as the board name on the silkscreen. Extra attention: the flyback diodes close to the fan connectors, the solder jumper and silkscreen text for the fan rail.

**Step 1 revised (2026-11-20, approved):** MCU alone with a 3.6 mm free ring, crystal next to the OSC pins, diagnostic LEDs in one row along the top edge, CAN ESD next to the CAN connector, the 9 fan ports as a regular 3 × 3 grid of identical cells (mechanical.md §9). Board stays 88 × 62 mm with all six LEDs.

**Step 2 (2026-11-20):** `scripts/pcbgen/dockboard_zones.py`, run after the placement script.
- Placement correction found while drawing the planes: the power input block is now placed first, right next to the XT30, so the unfused VIN_RAW runs 13.5 mm instead of 27 mm under the 5 V buck. The CAN ESD diode is also placed first (3.9 mm from J4) and the crystal group sits 3 mm higher to make room. CAN transceiver block at the top (37 mm from J4), SWD/buttons top right.
- In1 = solid GND plane (no AGND on the dock board). In2 = +24V_INT under the power input and 5 V buck, +24V_INT under the fan buck, FAN_RAIL under the fan grid with a band to JP_FRAIL / C_FRAIL / TP_FRAIL. The MCU escape ring stays free.
- No outer-layer power polygons: at ≤ 3.3 A a ≥ 1.6 mm track suffices (calculations.md §2.2; net class POWER_IN raised from 1.5 to 1.6 mm), and on this placement an F.Cu polygon would enclose pads of other nets. The power tracks are laid in step 3; outer GND pours and the catch-diode thermal copper follow in step 4.
- DRC: 0 errors; 2 × `isolated_copper` on the fan-buck +24V_INT plane (no via yet, resolved by stitching in step 3); unconnected items and silkscreen as expected before routing.

**Step 3 (2026-11-20):** `scripts/pcbgen/dockboard_route.sh` builds the board from scratch (placement, planes, routing; about 10 minutes).
- Placement corrections: the BOOT capacitors C_BOOT / C_FBOOT moved next to their buck's BOOT/SW pins (they were 10–14 mm away; C_FBOOT sits 1 mm inside the MCU ring). The fan grid moved 0.4 mm from the right edge (cell gap 0.8 mm) so the FAN_N tracks keep the edge clearance.
- `dockboard_preroute.py` lays the high-current copper by design: VIN_RAW 1.6 mm track, +24V_IN polygon (fuse → RPP FET source, TVS, LM74502), +24V_INT polygon at the FET drain with 6 vias 0.8/0.4 to In2, compact SW-node polygons for both bucks (SW pin, catch diode, inductor, BOOT capacitor), catch-diode anodes on a GND polygon with 3 vias 0.8/0.4 each, fan-buck output to a B.Cu FAN_BUCK plane (3 vias at the inductor), rail jumper JP_FRAIL with 0.8/0.4 vias on all three pins (FAN_RAIL: 1.0 mm track + 2 vias), and the USB-C pin pairs (DM joined left, DP right of the pads) to the ESD array.
- Planes: B.Cu FAN_BUCK plane under the fan buck, with a notch for the FB/COMP tracks; +24V_INT fan-buck plane reaches down to JP_FRAIL pin 1; FAN_RAIL plane has a tab to the JP_FRAIL pin 2 vias.
- Then `stitch.py` (plane-net pads to their plane), negotiated routing of all other nets (feedback nets first), maze for the rest. Router changes: track widths from the board's own net classes (`MAZE_WMAX`, dock 0.8 mm), vias may pass through In2 power planes (`MAZE_SOFT_PLANES`), stitching onto a B.Cu plane (`STITCH_B_PLANE`), duplicate same-net vias merged in `cleanup.py`.
- Result: 2,536 mm of track (F 1,732, B 517, In2 287), 350 vias, In1 an unbroken GND plane. USB D+/D− 40.8 / 41.7 mm, CANH/CANL 52.3 / 44.8 mm (uncritical at 12 Mbit/s and 1 Mbit/s).
- DRC: 0 errors, 0 unconnected, schematic parity OK. Warnings: silkscreen only (step 4). ERC 0.
- Known weak point: the fan buck's input capacitors (C_FIN1/2) sit about 12 mm from U_FBUCK VIN, so its input loop runs through the In2 +24V_INT plane. Acceptable for a 3 A buck on a solid GND plane; to verify on the prototype (switch-node ringing, rail ripple).

**Step 4 (2026-11-20):** part of `dockboard_route.sh` (the whole board, steps 1–4, from scratch in about 10 minutes).
- Placement: the fan rows are 2.1 mm apart and the grid starts right below the top-right hole keep-out, so every fan port has its label above it and the LED connector block keeps its place bottom right. Routing redone on this placement; the preroute script now also checks that none of its tracks or vias touches a pad of another net.
- GND pours (`pours.py`) on F.Cu, In2 and B.Cu below the power planes (power planes priority 2, scripted polygons 1, pours 0).
- Silkscreen (`dockboard_silk.py`, reusing the toolboard helpers, which now take the board size and can keep text off part bodies and mating plugs): `− FANx +` above every fan port (− = pin 1 FANx_N, + = pin 2 FAN_RAIL), fan rail jumper warning "RAIL JP: 24V | RAIL | BUCK / open = no fan power" (no room at the jumper itself: it sits about 14 mm away, below the MCU), "5V JP: cut = 12V" for the FB jumper (about 7 mm away), pin labels at SWD / CAN IN / LED, connector names, a label at every diagnostic LED and test point, board name + revision on top, the full identity block (name, revision, license, repository) on the bottom (AD-14).
- `dockboard/dockboard.kicad_dru`: THT GND pins next to routed tracks need only one spoke into an outer-layer pour (they also connect through the In1 plane and the other pour).
- DRC: 0 errors, 0 unconnected, schematic parity OK. Warnings: 8 × `lib_footprint_mismatch` (D7–D11, J1, J3, J4: edge silk trimmed on purpose, as on the tool board). ERC 0. 3D renders `out/render/dock_3d_top.png` / `dock_3d_bottom.png` (XT30, USB-C and Micro-Fit models missing in the KiCad library, open item 30).

## F7 — Production files and quote

1. Gerbers, drill, BOM and CPL in JLC format to `fab/rev-A/<board>/` (KiKit `fab jlcpcb` or `kicad-cli` + script).
2. Only `Assembly = JLC` in the BOM. `SELF` and `DNP` go in a separate list of hand-soldered parts, which Berten orders from LCSC.

4. **Berten** uploads the files to JLC for a quote and checks the placement preview. Update `design/30-cost-estimate.md` with the real figures.
5. Tag `rev-A` in git.

- Stock checked on 2026-11-20 for all 57 JLC parts and the 12 hand-soldered LCSC parts: all in stock (≥ 3× the need for 5 + 5 boards).
- Rotations: default table of kicad-jlcpcb-tools (`scripts/fab_rotations.csv`), plus two own entries by analogy (TI SO-PowerPAD-8, Infineon PG-TDSON-8). To be confirmed in the JLC placement preview (step 4).

## F8 — Firmware and Klipper configuration

1. Klipper `make menuconfig` settings for both boards (STM32G0B1, 128 KB, 8MHz crystal, USB or CAN or USB-CAN bridge) in `firmware/`.
2. Katapult configuration.
3. Klipper config: `[mcu toolboard]`, `[mcu dock]`, one include per tool (heater, thermistor, `filament_switch_sensor` and/or `filament_motion_sensor`), `heater_enable` (cutoff), MCU status LED, LEDs, fans. Motion sensors: link to the physical extruder and enable only the active tool's sensor in the tool change macro (`SET_FILAMENT_SENSOR`, open item 28).
4. **Commissioning macro** (architecture §9.5): per tool, briefly turn on one heater and check that **only** the matching thermistor rises. Otherwise `M112`.
5. **Cutoff startup self-test** (§9.6) via RAIL_SENSE.
6. **`M104/M109 Tn` compatibility** (§9.7) and **staggered heat-up** (§9.8). Test with OrcaSlicer, PrusaSlicer and Cura G-code.
7. Test plan for the first prototype: power-up without load, the voltage rails and their diagnostic LEDs, flashing, USB, CAN, one heater with cutoff test (incl. heater channel LED), all channels, filament runout + motion inputs, thermal test with 8 heaters cold, including the **main fuse body temperature** at 14 A continuous and during a cold start of all 8 heaters (calculations.md §7; board outside the heated chamber).
